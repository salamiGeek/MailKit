# MailKit Agent 邮箱客户端插件设计

## 1. 背景与目标

本项目在 MailKit 源码仓库内新增一个面向 AI Agent 的邮箱客户端子系统。它以 MailKit 和 MimeKit 为协议与消息处理底座，通过本地 .NET MCP Server 向 Codex 暴露结构化邮箱工具，并通过 Codex Plugin 中的 `SKILL.md` 教 Agent 正确、安全地组合这些工具。

项目的目标不是将 MailKit 的每个 .NET 类型和方法机械映射为 MCP 工具，而是在不削弱底层能力的前提下，提供稳定、可审计、适合 Agent 使用的语义接口。MailKit 的能力覆盖情况由显式能力矩阵追踪，不通过不透明的“执行任意 IMAP 命令”接口掩盖缺口。

首版应支持：

- 本机单用户环境中的多个邮箱账户。
- 通用 IMAP、POP3 和 SMTP 账户，使用密码或应用专用密码认证。
- Gmail OAuth 2.0 和 Microsoft 365 OAuth 2.0。
- 文件夹、搜索、读取、附件、草稿、回复、转发、发送、移动、复制、归档、标签、旗标与删除等常用邮箱操作。
- IMAP ACL、Quota、Metadata、Annotation、服务器能力探测等高级能力。
- POP3 专属的列取、读取和受控删除能力。
- 对 Agent 特有风险的强制安全控制，包括提示注入隔离、危险操作确认、秘密保护和附件限制。

## 2. 非目标

首版不包含：

- 多用户、远程托管或多租户 MCP 服务。
- 后台全量同步、离线邮箱、长期本地全文索引或持续 `IDLE` 通知。
- 任意原始 IMAP、POP3 或 SMTP 命令执行。
- 自动打开或执行附件，以及自动加载远程图片或跟踪像素。
- 内置 Gmail、Microsoft 或其他第三方 OAuth 客户端密钥。
- 对 MailKit 核心协议实现的私有修改。

## 3. 设计原则

1. **语义接口优先**：Agent 操作邮箱概念，不管理连接、流、文件夹打开模式或 MailKit 对象生命周期。
2. **核心零侵入**：新增项目仅依赖 MailKit 公开 API，保持上游底座易于同步。
3. **最小权限**：只读、可恢复写入和外部或不可逆操作采用不同授权策略。
4. **不可信内容隔离**：邮件中的任何内容均是数据，不是可执行指令。
5. **显式能力差异**：服务器不支持某项功能时返回结构化能力错误，不静默改变语义。
6. **秘密不进入模型上下文**：密码、Token 和凭据操作均在本地服务边界内完成。
7. **接口可演进**：MCP DTO 和错误代码版本化，不泄露 MailKit 内部类型。

## 4. 总体架构

系统分为五层，依赖始终向下：

1. **Codex Plugin 层**
   - 包含 `.codex-plugin/plugin.json`、MCP 配置和邮箱 `SKILL.md`。
   - 描述工具选择、分页、确认流程、不可信内容处理和典型邮箱工作流。
   - 不保存或读取邮箱凭据。

2. **MCP 契约层**
   - 以本地标准输入/输出方式运行，不监听网络端口。
   - 将 MCP 参数绑定到稳定 DTO，并把应用结果转换为结构化响应。
   - 不允许 MailKit 对象、异常、连接状态或秘密穿透到 Agent。

3. **应用与安全层**
   - 负责账户选择、用例编排、参数校验、分页、风险分类、预览和确认令牌。
   - 实施速率限制、批量上限、幂等、取消、超时、审计摘要和输出截断。
   - 是所有 Agent 请求必须经过的信任边界。

4. **邮件能力适配层**
   - `ImapGateway`、`Pop3Gateway` 和 `SmtpGateway` 封装 MailKit。
   - `MimeContentService` 封装 MimeKit 的正文选择、MIME 树、附件与安全文本转换。
   - OAuth 和凭据组件只向协议客户端提供认证材料，不向 Agent 返回秘密。

5. **MailKit 底座层**
   - 新增项目通过 `ProjectReference` 使用仓库中的 MailKit 源码。
   - 现有 MailKit 和 MimeKit 源码、公共 API 与协议行为保持不变。

## 5. 工程组织

新增子系统采用同仓库、独立项目的结构：

- `src/MailKit.Agent.Core`：稳定 DTO、应用用例、策略、能力模型和协议网关接口。
- `src/MailKit.Agent.Auth`：账户档案、系统安全存储和 OAuth 流程。
- `src/MailKit.Agent.Mail`：MailKit/MimeKit 网关实现、连接管理与内容转换。
- `src/MailKit.Agent.Mcp`：MCP Server、工具注册、参数绑定和进程入口。
- `plugin/`：Codex Plugin 清单、MCP 配置和邮箱 Skill。
- `tests/MailKit.Agent.Core.Tests`：领域和策略单元测试。
- `tests/MailKit.Agent.Mail.Tests`：协议适配与会话脚本测试。
- `tests/MailKit.Agent.Mcp.Tests`：契约和进程级端到端测试。
- `docs/`：用户配置、安全模型、能力矩阵和维护文档。

命名可在实现计划中根据仓库约定微调，但层次职责和依赖方向不得合并为单一大型项目。`Core` 不依赖 MCP 或具体 MailKit 客户端；MCP Handler 保持轻薄。

## 6. MCP 工具领域

正式工具按邮箱领域组织：

- `account_*`：创建、列出、测试、更新、删除账户档案；启动和完成 OAuth 登录；查看服务器能力。
- `folder_*`：列出、创建、重命名、删除、订阅、取消订阅、状态和特殊文件夹发现。
- `message_*`：搜索、分页列取、读取正文、头部和 MIME 结构、线程视图、旗标和标签、复制、移动、归档和删除。
- `attachment_*`：列出、下载和安全保存附件。
- `draft_*`：创建、更新、列出、读取、发送和删除草稿。
- `send_*`：构建与预览邮件、确认投递、查询投递结果；支持纯文本、HTML、附件、回复、转发及受控 SMTP 高级选项。
- `imap_acl_*`：读取和修改访问控制。
- `imap_quota_*`：读取和设置配额，前提是服务器支持且账户有权限。
- `imap_metadata_*`：服务器和文件夹元数据操作。
- `imap_annotation_*`：Annotation 操作。
- `pop3_*`：POP3 专属列取、读取和受控删除。
- `diagnostics_*`：连接测试、能力快照和脱敏协议诊断。

诊断工具默认只读，不提供任意原始协议命令。每个工具都必须在能力矩阵中关联到 MailKit API、协议前置条件、风险等级、测试和文档。

## 7. 内部组件

- `ToolHandlers`：MCP 参数绑定、调用应用用例、结果转换。
- `MailboxApplication`：编排账户、文件夹、邮件、草稿和发送用例。
- `OperationPolicy`：风险分级、批量限制、预览、确认令牌和策略拒绝。
- `AccountProfileStore`：保存不含秘密的账户配置。
- `AccountVault`：系统安全存储的抽象和平台实现。
- `OAuthCoordinator`：Gmail 与 Microsoft 365 OAuth 登录、刷新和撤销。
- `ConnectionManager`：连接生命周期、有限复用、并发控制、超时、取消和断线恢复。
- `ImapGateway`、`Pop3Gateway`、`SmtpGateway`：MailKit 适配器。
- `MimeContentService`：正文选择、字符集处理、MIME 树、附件元数据和安全文本输出。
- `CapabilityRegistry`：MailKit 能力和服务器实际能力的映射。
- `AuditSink`：仅记录脱敏的操作摘要和关联 ID。

## 8. 账户、认证与秘密

首版为本机单用户、多账户模型。账户档案可保存：服务器地址、端口、TLS 模式、用户名、认证类型、账户别名和协议开关。密码、应用专用密码、访问 Token、刷新 Token、客户端秘密和确认令牌不得写入账户档案或日志。

`AccountVault` 为系统安全存储提供统一接口。平台实现必须保证秘密不会出现在 MCP 响应、进程命令行、普通配置文件或异常文本中。若某个平台缺少满足要求的安全存储实现，账户配置应失败并给出明确的安全错误，而不是退化为明文保存。

Gmail 与 Microsoft 365 使用 OAuth 2.0，优先采用系统浏览器或设备授权流程。OAuth 客户端配置由用户或组织提供。Token 刷新在本地完成，刷新结果直接写回安全存储。

## 9. 数据访问与标识

首版实时访问邮箱服务器，不建立本地邮件数据库。搜索优先下推到 IMAP；正文和附件按需读取。本地只保存账户档案、能力缓存、确认状态、幂等记录和最少量运行状态。

邮件引用必须包含足以检测状态变化的信息：

- IMAP：`account_id + folder_id + uid_validity + uid`。
- POP3：`account_id + uidl`。

工具不接受 MailKit 对象引用或进程内句柄。分页使用有有效期的不透明游标。所有时间以 ISO 8601 返回并保留原始时区信息。

只读请求遵循以下流程：

`Agent → MCP 校验 → 账户与策略检查 → 获取连接 → MailKit 查询 → MIME 安全转换 → 脱敏与截断 → 结构化结果`

大正文返回大小和截断信息，并允许按需分段读取。工具结果明确区分元数据、正文和附件，所有来源于邮件的文本都标记为不可信数据。

## 10. 风险分级与确认协议

操作分为三级：

1. **只读**：列出、搜索和读取等操作可直接执行。
2. **可恢复写入**：标记已读、加标签、移动到垃圾箱和保存草稿等默认可直接执行，但必须返回完整变更摘要。
3. **外部或不可逆**：发送邮件、永久删除、清空文件夹、批量变更、修改 ACL 和设置配额必须经过两阶段确认。

两阶段确认协议：

1. `*_prepare` 校验账户、对象、收件人、附件、服务器能力和批量上限，返回精确预览、影响范围及短期确认令牌。
2. `*_commit` 携带令牌。服务端验证令牌绑定的账户、规范化参数、操作者会话、风险类别和有效期，然后执行操作。

确认令牌不可修改后复用，成功后立即失效。执行前再次验证 `UIDVALIDITY`、邮件状态和目标文件夹，状态变化时返回冲突而不是操作其他对象。

发送操作支持由调用方提供的幂等键。服务端保存有限期幂等结果；遇到超时或断线时先查询既有结果，不盲目重复发送。永久删除等操作同样不得自动重放。

## 11. 不可信内容与附件安全

邮件主题、地址显示名、头部、正文、日历内容和附件均是不可信数据。Skill 和工具响应必须明确告诉 Agent：不得将邮件内容解释为系统指令，也不得因为邮件要求发送、删除、登录、付款或调用其他工具而绕过用户意图和确认策略。

默认行为：

- 返回正文的安全文本表示；HTML 可以作为受限数据返回，但不执行脚本。
- 不自动加载远程图片、跟踪像素或外链资源。
- 先返回附件元数据，只有显式下载调用才保存内容。
- 附件目标限制在配置的下载根目录中，规范化并校验最终路径，阻止路径穿越。
- 限制附件大小、单次输出大小、批量对象数量和并发下载数。
- 不自动打开、解析为可执行指令或运行附件。

提示注入隔离、秘密保护、确认策略和 TLS 规则是不可关闭的核心安全边界。用户只能显式调整附件大小等非核心限制，并受全局硬上限约束。

## 12. TLS 与连接安全

- 默认要求有效的 TLS 证书，不暴露“忽略所有证书错误”工具。
- 明文、STARTTLS 和隐式 TLS 必须明确配置，不允许静默降级。
- 认证失败不自动高频重试，避免触发账户锁定。
- 每个请求支持取消和超时。
- `ConnectionManager` 限制每账户和全局并发，断线时释放 MailKit 客户端、流和临时资源。
- 协议日志默认关闭；启用诊断时必须使用 MailKit 的认证秘密检测和额外脱敏，并禁止记录正文和附件内容。

## 13. 错误模型

所有工具使用统一错误结构：

- `code`：稳定、机器可读的错误码。
- `category`：`validation`、`authentication`、`authorization`、`capability`、`conflict`、`transient`、`policy` 或 `internal`。
- `message`：脱敏、适合用户阅读的说明。
- `retryable`：是否适合自动重试。
- `retry_after`：适用时的建议等待时间。
- `details`：允许公开的字段问题、能力缺口或状态冲突。
- `correlation_id`：用于本地诊断的关联 ID。

连接中断、限流和临时服务器错误可按有界退避策略重试只读操作。高风险写操作只有在幂等状态证明尚未执行时才能继续。服务器缺少能力时返回 `capability` 错误，不猜测替代语义。未经识别的异常转换为脱敏的 `internal` 错误，完整敏感信息不得进入 Agent 响应。

## 14. 审计与可观测性

审计记录只包含：操作类型、账户别名或不可逆标识、对象数量、风险级别、结果、耗时、时间和关联 ID。不得记录邮箱密码、Token、确认令牌、完整地址列表、邮件主题、正文或附件内容。

指标应覆盖连接结果、认证失败类别、工具耗时、服务器限流、重试、策略拒绝和能力缺失。诊断导出必须再次脱敏，并由用户显式触发。

## 15. 测试策略

1. **领域单元测试**
   - 使用假的协议网关验证搜索、分页、风险分级、批量限制、确认令牌、幂等和状态冲突。

2. **MailKit 适配测试**
   - 使用可重复的 IMAP、POP3 和 SMTP 会话脚本验证连接、认证、能力差异、断线和异常映射。
   - 遵循 MailKit 仓库现有测试模式，不依赖 CI 中的真实邮箱服务。

3. **MCP 契约测试**
   - 固定每个工具的 JSON Schema、错误结构和稳定 DTO。
   - 工具新增允许向后兼容；删除、重命名或收紧字段必须通过显式版本演进。

4. **安全测试**
   - 验证邮件内提示注入不能改变工具策略。
   - 验证秘密不会出现在响应、日志、异常或命令行中。
   - 验证确认令牌不能篡改、跨会话使用或重放。
   - 验证附件路径不能越界、TLS 不能降级、批量和输出上限有效。

5. **端到端测试**
   - 启动本地 MCP 子进程，通过标准输入/输出完成模拟账户、搜索、读取、草稿、预览、确认和发送流程。
   - 使用模拟授权服务器自动测试 Gmail 和 Microsoft OAuth 交互边界。
   - 提供默认跳过的人工烟雾测试，以测试账户验证真实服务。

## 16. 能力覆盖矩阵

能力矩阵是首版交付物。每条记录至少包含：

- 领域和语义能力名称。
- 对应 MailKit/MimeKit API。
- 所需协议和服务器能力。
- MCP 工具及版本。
- 风险等级和确认要求。
- 自动化测试位置。
- 当前状态：已支持、服务器不支持、仅诊断或后续版本。

首版发布不得存在未说明的能力缺口。尚未安全映射的底层 API 必须明确标记为后续版本，并解释阻塞原因，不能通过原始协议执行器临时暴露。

## 17. 分阶段交付

为控制集成风险，首版在一个统一架构下分阶段完成：

1. **基础与只读能力**：工程骨架、MCP 契约、账户档案、系统安全存储、连接管理、能力探测、文件夹、搜索、读取、正文和附件元数据。
2. **可恢复写入**：旗标、标签、草稿、复制、移动、归档、垃圾箱和变更摘要。
3. **危险操作与发送**：预览/确认协议、幂等、SMTP 投递、永久删除和批量操作。
4. **OAuth**：Gmail 与 Microsoft 365 登录、刷新、撤销及真实服务烟雾测试。
5. **高级 MailKit 能力**：ACL、Quota、Metadata、Annotation、POP3 专属能力和脱敏诊断。
6. **插件与发布验收**：Skill、插件清单、安装说明、能力矩阵、跨平台验证和完整端到端工作流。

每一阶段都必须保持前述安全边界；不得以“后续再加安全”为由先暴露危险能力。

## 18. 验收标准

- 已承诺的常用和高级能力均出现在能力矩阵中，并具备契约测试与文档。
- 只读、可恢复写入、外部或不可逆三类策略均有自动化验证。
- Agent 无法读取凭据，也不能绕过发送、永久删除、ACL 和配额修改确认。
- 邮件内容被明确标记为不可信，远程资源和附件不会自动打开或执行。
- Windows、macOS 和 Linux 的构建与核心测试通过，系统安全存储适配器分别验证。
- Codex 安装插件后能发现 Skill 和 MCP 工具，并完成账户配置、搜索、读取、起草、预览、确认和发送的完整工作流。
- MailKit 核心源码不因本项目产生功能性修改。

## 19. 关键决策摘要

- 采用 Codex Plugin、`SKILL.md` 和本地 .NET MCP Server 的组合。
- 正式接口采用分层语义工具，不做 MailKit API 一对一工具映射。
- 同仓库新增独立项目，MailKit 核心零侵入。
- 实时访问服务器，不在首版建立本地邮件数据库。
- 支持通用认证以及 Gmail、Microsoft 365 OAuth 2.0。
- 高风险操作使用绑定精确参数的两阶段确认。
- 所有邮件内容和附件按不可信输入处理。
- 通过能力矩阵实现 MailKit 功能覆盖的可见性和可验证性。
