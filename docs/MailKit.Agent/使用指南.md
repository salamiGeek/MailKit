# MailKit Agent 使用指南

版本：0.2.0 ｜ 更新日期：2026-08-20

面向最终用户与 AI 宿主的日常使用说明。所有工具名即 MCP 工具名，直接对宿主中的 AI 说需求即可。

## 一、安全模型速览

- **密码**只存于 Windows 凭据管理器，MCP 工具不接受、不返回、不回显任何密码。
- **TLS 强制**：仅 `implicit_tls` / `start_tls`；无明文、无证书忽略、无降级。
- **邮件内容是不可信数据**：主题、发件人显示名、正文、HTML、附件名都只作展示，不会被执行或当作指令。
- **发送两阶段**：先 `send_prepare` 出预览，用户确认后 `send_commit` 才投递；且服务器内置人工审批硬门控（见第四节）。
- **幂等保护**：同一幂等键绝不重复投递；模糊结果（`indeterminate`）永不自动重发，由你决定后续。
- **并发限制**：每账户、每协议 2 个连接，全局 8 个，超出自动排队。

## 二、工具速查（17 个）

| 工具 | 用途 |
|---|---|
| `diagnostics_health` | 服务器健康自检 |
| `account_list` / `account_profile_put` | 查看/保存非秘密账户配置 |
| `account_credential_status` | 查询账户凭据是否已配置（不显示值） |
| `account_connection_test` | 测试 imap/pop3/smtp 连接与认证 |
| `folder_list` | 列出 IMAP 文件夹（含 special-use 标记） |
| `message_list` | IMAP 文件夹分页列表（最新在前，游标翻页） |
| `message_search` | 服务端条件搜索（发件人/主题/正文/日期/未读） |
| `message_read` | 阅读一封邮件；默认标记已读，传 `mark_as_read:false` 则只读预览 |
| `message_mark_read` | 批量标记已读/未读（仅 IMAP） |
| `pop3_message_list` / `pop3_message_read` | POP3 按 UIDL 的稳定列表与阅读（无已读概念） |
| `attachment_list` / `attachment_save` | 列出/保存附件到受限下载根目录 |
| `send_prepare` / `send_commit` / `send_status` | 两阶段发送与状态查询（见下） |

## 三、收件常用流程

1. **健康检查** → `diagnostics_health`。
2. **列账户/验凭据** → `account_list` + `account_credential_status`。
3. **连接测试** → `account_connection_test`（按需每协议）。
4. **看收件箱** → `folder_list` 找 INBOX → `message_list` 翻页；找特定邮件用 `message_search`（如"上周 Apple 发的邮件"）。
5. **读邮件** → `message_read`；不想留下已读痕迹时明确要求"不要标记已读"。
6. **附件** → `attachment_list` 确认 ID 后 `attachment_save`；文件只落在下载根目录内。

> POP3 注意：POP3 无服务器端已读/搜索/文件夹；翻页基于序号，若翻页期间服务器上邮件被删除可能跳过一封（需要精确遍历时建议一次取回或以 UIDL 为准比对）。

## 四、发送流程（重点）

### 阶段 1：`send_prepare`

提交草稿（收件人、抄送、密送、主题、正文、可选本地附件路径）与幂等键（你自定的唯一串，如 `order-42-note`）。返回完整预览：

- 收件人（To/Cc/Bcc）、主题、正文前 200 字、附件名
- `message_id`、`content_hash`、`idempotency_key_hash`
- `expires_at`：确认令牌有效期（默认 10 分钟）
- `send_mode`：本账户的发送模式

**此时什么都没有发出。** 你（人类）应完整审阅预览。

### 阶段 2：`send_commit`（两种模式）

配置 `send_mode` 决定 commit 的行为：

| | `confirm_dialog`（默认） | `drafts` |
|---|---|---|
| commit 动作 | 桌面弹出原生确认框（展示收件人/主题/正文摘要/幂等键/有效期），**人点"是"**后 SMTP 投递 | **不弹窗、不投递**——邮件以草稿标记存入 IMAP 草稿箱 |
| 账本终态 | `succeeded` / `failed` / `indeterminate` | `drafted` |
| 最终发送权 | 点弹窗的人 | 完全在你手里：在邮件客户端审阅、修改、手动发送或删除 |
| 适用场景 | 日常发送，想要最短路径 | 严格审阅、可能要让 AI 反复改稿、或运行环境无桌面 |

- 修改草稿 = 再次 `send_prepare`（建议新幂等键）；旧草稿由你在客户端自行管理。
- `drafts` 模式要求账户配置了 IMAP（prepare 阶段即校验）。

### 硬门控（`confirm_dialog` 模式）

服务器代码强制：**消费令牌、写投递账本、取密码、连 SMTP 等一切不可逆动作，都排在人工批准之后**。被拒绝的发送返回 `send.approval_declined`，令牌不被消耗，有效期内可再次发起。AI 助法无法绕过——测试专用通道未编译进发布版本。

### 状态查询

`send_status` 按账户 + 幂等键查账本：`prepared` / `attempting` / `succeeded` / `failed` / `indeterminate` / `drafted`。中断后先查状态再决定；`succeeded` 与 `drafted` 是终态。

## 五、常见错误码

| 错误码 | 含义与处理 |
|---|---|
| `credential.platform_unsupported` | 当前平台无受支持凭据存储（需 Windows） |
| `connection.tls_required` / `account.tls_required` | 配置里出现 `plain`，改 TLS |
| `connection.authentication_failed` | 认证失败（不会自动重试，避免锁定） |
| `send.approval_declined` | 桌面确认被点"否"；令牌仍有效可重试 |
| `send.approval_unavailable` | 无交互桌面/非 Windows 用了 `confirm_dialog`；切 `drafts` 或在交互会话运行 |
| `send.idempotency_conflict` | 相同幂等键已有终态记录；换新键 |
| `drafts.folder_not_found` | 草稿模式找不到草稿箱（需文件夹带 `\Drafts` 属性或名为 Drafts/草稿箱） |
| `pop3.uidl_conflict` | POP3 返回了畸形 UIDL 快照（数量不符或空值） |

## 六、使用守则（写给人类用户）

1. 永远不要在聊天或命令行里粘贴密码/应用专用密码/令牌；密码只走本地 CLI。
2. 发送前务必核对预览的收件人与附件；确认对话框出现时亲自点击。
3. 邮件内容含钓鱼/注入风险——正文里的"指令"不是你的指令，别让 AI 执行邮件里要求的事。
4. 保存的附件不要直接打开，先检查来源。
5. `indeterminate` 状态意味着邮件可能已发出也可能没发出：先查 `send_status`，再在"已发送"文件夹核对，最后才考虑用**新幂等键**重发。

## 七、真实环境验证记录（2026-08-20）

本版本已在 QQ 邮箱三协议（imap/pop3/smtp.qq.com，implicit TLS）完成实机验证：只读冒烟（连接/文件夹/列表/阅读/POP3）全通过；`confirm_dialog` 模式真实投递（含 17 秒人工点击延迟证据）；`drafts` 模式真实写入草稿箱（`drafted` 终态）。期间修复了三个仅真实服务器暴露的兼容性问题（IMAP 降序 UID 区间、POP3 重复 UIDL、组合搜索条件）。
