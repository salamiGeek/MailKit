# MailKit Agent 升级指南

版本：0.2.1 ｜ 更新日期：2026-08-20

本指南说明如何把已部署的 MailKit Agent 更新到新版本。首次安装请先阅读[部署指南](./部署指南.md)；日常使用见[使用指南](./使用指南.md)。

## 一、确认当前版本与是否需要升级

让宿主里的 AI 调用 `diagnostics_health`，查看 `version` 字段：

| 已部署版本 | `diagnostics_health` 回报 | 建议 |
|---|---|---|
| 0.2.1 及以上 | 真实版本号 | 按需升级 |
| 0.2.0 | `0.1.0`（历史版本未同步回报） | **建议升级到 0.2.1** |

**0.2.0 → 0.2.1 变更内容**：

- 修复：`send_prepare` 成功后，若 MCP 宿主在两次调用之间重启了服务器进程（或代理链路为每次调用拉起新进程），`send_commit` 必然返回 `send.invalid_confirmation` 的问题。修复后确认令牌在 10 分钟有效期内跨服务器重启可用（签名密钥按数据目录持久保存，Windows 上以 DPAPI 保护）。
- 修复：`diagnostics_health` 开始回报与插件清单一致的版本号。
- 兼容性：账户配置、凭据（Windows 凭据管理器）、发送账本、下载目录全部原样兼容，**无需任何数据迁移**。

## 二、发布侧：构建新版本插件

在源码仓库执行（Windows，.NET SDK 8.0.x）：

```powershell
# 1. 切到目标提交（含修复），确认工作区干净
git status

# 2. 发布插件服务器（脚本会清空并重建 plugins/mailkit-agent/server/，完成后自动校验必需文件）
.\scripts\Publish-MailKitAgentPlugin.ps1 -Runtime win-x64

# 3. （分发包时）打包 zip
Compress-Archive -Path plugins\mailkit-agent\* -DestinationPath output\mailkit-agent-0.2.1-win-x64.zip -Force
```

**发布检查单（每次发版必须执行）**：`plugins/mailkit-agent/.codex-plugin/plugin.json` 的 `version` 与 `src/MailKit.Agent.Core/Contracts/ServerInfo.cs` 中的版本号**两处同步修改**——`diagnostics_health` 回报的是后者，部署方靠它确认升级生效。

## 三、部署侧：更新已部署环境

### 方式 A：通用 MCP 宿主（Claude Code、Cursor 等）

1. **退出宿主**（或断开 MCP 连接），确认没有残留的 `mailkit-agent` 进程（任务管理器或 `Get-Process mailkit-agent`）。
2. 备份现有部署目录（如 `C:\Tools\mailkit-agent\`，可选但推荐）。
3. 解压新包（或复制 `plugins/mailkit-agent/` 整个目录）覆盖部署目录。数据目录不在这里，不受影响。
4. 重启宿主 / 重载 MCP 连接。
5. 按第四节清单验证。

### 方式 B：Codex 插件宿主

1. 退出宿主，确认无残留进程。
2. 用新的 `mailkit-agent/` 目录整体替换插件目录中原有的目录（保留 `.codex-plugin/` 结构）。
3. 重启宿主，按第四节清单验证。

## 四、升级验证清单

- [ ] `diagnostics_health` 回报 `version: "0.2.1"`
- [ ] `account_list` 能列出账户且 `send_mode` 正确
- [ ] `account_connection_test` 各协议 connected / tls / authenticated
- [ ] drafts 模式试跑：`send_prepare` → `send_commit` → `send_status` 报告 `drafted`，邮件客户端刷新后草稿箱出现新草稿
- [ ] （针对本次修复）`send_prepare` 后**重启宿主**再 `send_commit`，仍应成功保存草稿

## 五、数据目录说明与遗留记录清理

数据目录（默认 `%LOCALAPPDATA%\MailKit.Agent\`）升级前后对比：

| 内容 | 升级影响 |
|---|---|
| `accounts\`（账户配置） | 原样保留，无需操作 |
| Windows 凭据管理器中的密码 | 不受影响（与部署目录无关） |
| `send-ledger\`（发送账本） | 格式兼容，历史记录可继续查询 |
| `send-confirmation.key` | **0.2.1 首次启动自动生成**（DPAPI 当前用户加密），无需预创建 |
| `send-preparations\` | **0.2.1 首次启动自动创建**，准备记录 TTL 过期后随访问清扫 |
| `downloads\`（附件） | 原样保留 |

两点说明：

- **0.2.0 遗留的卡死记录**：升级前因该 bug 卡在 `prepared` 状态的账本条目（`send_status` 永远停在 `prepared`、`attempted_at` 为 null）不影响新发送——用新的 `idempotency_key` 即可。如想清理，直接删除 `%LOCALAPPDATA%\MailKit.Agent\send-ledger\<账户>\<key-hash>.json`。
- **DPAPI 与 Windows 用户的绑定**：`send-confirmation.key` 只能由创建它的同一 Windows 用户解密。若宿主换了运行账户，首次启动会自动重建密钥（未提交的确认令牌随之失效，安全回退），无需人工干预。

## 六、回滚

用升级前的备份（或旧版包）换回部署目录即可。旧版本代码不会读取 `send-confirmation.key` 与 `send-preparations\`（它们只是被忽略的普通文件），账本格式双向兼容。回滚后的行为回到"确认令牌跨进程重启失效"，若再次遇到 `send.invalid_confirmation`，参照本指南重新升级。
